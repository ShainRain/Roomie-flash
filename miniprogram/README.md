# Roomie · 一间有音乐的放映室

> 腾讯音乐首届高校 AI 黑客松参赛作品（赛道二 · 独立创新产品）
> **Meet your people through music & films.** —— 以音乐和电影为媒介的"同频陪伴"轻社交小程序。

---

## 一、产品定位与用户价值

**目标用户**：18–28 岁、深夜独自听歌/看电影的年轻人——他们有陪伴需求，但厌恶主动社交的压力。

**真实痛点**：深夜听歌看电影是高频独处场景；"一起听"类产品解决了同步，却没有解决"空间感"和"低压力破冰"——邀请好友像发消息一样生硬。

**Roomie 的解法**：每个人都有一间可 DIY 的等距 2.5D「虚拟放映室」——黑胶唱片墙、沙发、投影幕布。邀请好友不是发一条消息，而是"来我家坐坐"。

- **同频陪伴**：与好友在同一房间同步听歌/放映，实时"同频度"可视化（同频 98%）
- **低压力社交**：房间即名片——唱片墙、装修风格替用户开口说话
- **收藏反哺装饰**：收藏的黑胶唱片可直接挂上房间墙，听歌行为沉淀为个人空间

## 二、差异化

| 对比项 | 传统"一起听" | Roomie |
|---|---|---|
| 载体 | 一条播放链接 | 可 DIY 的 3D 感个人空间 |
| 破冰 | 文字邀请 | "来家里"的空间邀请 + 角色互动动作 |
| 留存钩子 | 歌单 | 房间装修、唱片墙收集、明信片分享裂变 |

**AI 叙事（路演展开）**：房间插画与美术资产全部由"AI 代码生成管线"生产（Python 程序化生成 SVG → PS 滤镜批处理），同一管线可演进为"AI 根据用户歌单口味自动生成房间风格"——这是可行性故事里 AI 带来的新能力突破。

## 三、演示路径（5 分钟）

1. **首页**：LIVE 胶囊「深夜放映室 · 放映中」→ 点 ▶ 播放，黑胶旋转、进度走秒
2. 点房间插画 → **房间直播页**（沉浸式全屏房间 + 悬浮播放器）
3. 点播放器 → **歌曲详情页**（黑胶唱机 + 唱针起落、歌词随进度滚动高亮、拖动 seek）
4. 好友 Tab → 点 KIKI「进入」或 NANA「邀请」（模拟接受弹窗）→ **双人同频页**（同频 98% 圆环、歌单控制权标识、退出确认）
5. 消息 Tab → 「接受」邀请直达双人房
6. 中央 + → **建筑师模式**（家具多选、地板换色、灯光色温 2700K→6000K 实时渲染）→ 保存
7. 回到房间页：灯光色温已应用（DIY 反映到房间）
8. 我的 Tab → **唱片墙布置**（24 选 12，保存持久化）
9. + → 生成明信片 → **建筑明信片**（canvas 海报，保存相册 / 转发好友）

## 四、运行方式

1. 微信开发者工具 → 导入项目 → 选择本仓库根目录（`project.config.json` 已配置 `miniprogramRoot`）
2. AppID 选择「测试号」即可
3. 主包约 620KB（含分层场景资产），无网络依赖，全部 mock 数据本地运行

## 五、技术架构

```
miniprogram/
├── app.js / app.json / app.wxss   # 全局数据、设计令牌（色板/字号/圆角）
├── custom-tab-bar/                # 自定义 Tab 栏（纯 CSS 图标 + 中央创建按钮）
├── utils/player.js                # 全局播放器状态机（单例 + 订阅发布）
├── assets/img/                    # webp 美术资产（~216KB，sharp 压缩管线）
└── pages/
    ├── home/       首页（LIVE 态 + 好友在线 + 内嵌播放器）
    ├── room/       房间直播页（沉浸全屏 + DIY 灯光叠加）
    ├── song/       歌曲详情页（黑胶唱机 + 歌词滚动高亮）
    ├── friends/    好友页（在线/离线分组 + 邀请流程）
    ├── duo/        双人同频页（同频度 + 控制权）
    ├── messages/   消息页（邀请通知）
    ├── create/     创建入口聚合
    ├── architect/  建筑师模式（DIY 编辑器）
    ├── profile/    我的放映室（角色 + 唱片墙）
    └── postcard/   建筑明信片（canvas 海报生成）
```

- **零第三方框架**：微信原生 WXML/WXSS/JS，无构建步骤
- **播放器状态机**：`utils/player.js` 单例管理 mock 歌单、模拟走秒、切歌/seek、歌词时间戳索引；页面通过订阅快照驱动 UI，三页（首页/房间/歌曲）状态天然同步；`applyRemote()` 接收对端播放状态（2.5s 容差 + sentAt 延迟补偿，remote 标记防回播）
- **本地持久化**：房间 DIY（`roomie_room`）、唱片墙选择（`roomie_records`）写入 storage；房间页/双人页/建筑师/明信片均实时读取同一份状态——DIY 不再是"只存数据"，家具显隐、碰撞区域、唱片墙槽位、明信片封面全部联动
- **美术管线**：`gen_*.py`（Python 程序化生成等距 SVG）→ Photoshop JSX 滤镜批处理；房间场景由 `tools/gen-room-scene.js`（Node + sharp）分层生成：底图 + 13 件家具透明覆盖层 + 24 张唱片封面板材 + 统一双色图标 + `utils/room-layout.js` 布局元数据
- **房间角色交互**：房间页支持点击任意位置移动角色——可行走区域为贴合底图的地板菱形（uv 参数化约束），网格 A* 寻路绕开家具，角色按纵深缩放并与家具按 z 序遮挡；点击在线角色会在距离足够近时触发挥手、击掌、一起听歌动作。双人页提供同样的移动与互动演示
- **DIY 家具真实生效**：建筑师模式保存的家具选择直接决定房间层的显隐与碰撞（`room-map.js setActiveFurniture`）；唱片墙 24 选 12 真实映射到墙面 12 个槽位（未选显示空槽），明信片同步使用当前选择
- **临时角色资产**：当前个人角色 MOMO 使用橙色圆润形象，联机角色 KIKI 使用黄色奶龙形象；资源由 `tools/prepare-character-assets.js` 从本机白底参考图提取透明背景并生成 `idle / walk-a / walk-b / sit` WebP。参考图仅用于临时演示，正式发布前需替换为已授权或原创素材。
- **空间视觉参考**：房间布局采用"生活化排练室 + 小型唱片画廊"语法：保留乐器、音箱、线材和轻度使用痕迹，同时用木质层板、规则网格、混合海报与黑胶陈列建立秩序。外部参考图只用于提炼布局规律，运行时使用原创抽象封面或已授权素材。
- **可玩房间物件**：唱片墙、唱机柜、放映机、沙发、落地灯、吉他角和地面唱片均有独立点击区域与状态；标签默认隐藏，角色靠近或点按时浮现；可切换观影模式、开关灯光、播放唱片、坐下休息、弹吉他，投影光束、唱机旋转、音符飘浮和提示气泡随状态变化。
- **视觉资产替换约定**：当前房间使用 `assets/img/room-interactive.webp`（828×828 等距底图，由 `tools/gen-room-scene.js` 程序化生成），替换时保留该尺寸与对称墙角；家具布局变化后，同步调整 `utils/room-map.js` 的障碍物与 `tools/gen-room-scene.js` 中的家具坐标，并运行 `node tools/test-room-map.js` 验证可行走区域。

## 七、多人实时同步（Demo 期：本地中继）

```
小程序 A（模拟器/真机）                    小程序 B（真机/模拟器）
  utils/room-sync.js                     utils/room-sync.js
        │  ws://<HOST>:8765                    │
        └──────────►  tools/sync-server.js  ◄──┘
            （房间制中继：join/move/state/player/action 广播，
              player 状态按房间缓存，新加入者补发）
```

- **客户端** `utils/room-sync.js`：加入房间（单实例 + connecting 守卫，幂等）、位置节流广播（150ms）、家具状态、互动动作与**播放器状态**同步；**断线自动回退为模拟 peer**（本地游走），页面无感知
- **播放同步协议**：`{ type:'player', index, position, playing, sentAt }`；本地切歌/播放暂停/seek 跳变即时报，播放中每 5s 心跳校正；对端 `Player.applyRemote()` 按 2.5s 容差应用，last-write-wins
- **服务器** `tools/sync-server.js`：`node tools/sync-server.js` 启动（依赖 `ws`，已在 tools/node_modules）
- **模拟器**直连 `127.0.0.1`；**真机**把 `room-sync.js` 顶部 `HOST` 改为电脑局域网 IP（同网段）
- 行为测试：`node tools/test-sync.js`（10 项断言：成员列表/移动/状态/动作/播放状态广播、无回声、晚加入者缓存补发、离开通知）
- **决赛期迁移路径**：替换为云开发实时数据库（`db.watch`）或腾讯云 IM/TRTC 信令，页面侧接口不变
