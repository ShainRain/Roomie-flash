# Roomie 微信小程序规格文档

> 规格版本：1.0（2026-10-04）
> 依据：`docs/project/PLAN.md`、`docs/project/PROGRESS.md`、`docs/competition/SUBMISSION.md`、`docs/competition/DEMO-SCRIPT.md`、`miniprogram/README.md` 及当前代码。

## 1. 文档职责声明

本文档是 Roomie Demo 的行为、视觉和验收基准。

- 本文档定义“必须交付”的用户行为、状态边界、页面职责和验证证据。
- `miniprogram/` 是运行时行为的事实来源；当文档与代码冲突时，先修正文档或提出变更，再修改实现。
- `docs/project/PLAN.md` 负责排期，`docs/project/PROGRESS.md` 负责事实记录，`docs/competition/DEMO-SCRIPT.md` 负责讲解顺序，本文档不替代它们。
- 需求使用规范性词语：**必须**表示验收门槛，**应该**表示默认实现，**可以**表示非阻塞增强。
- 任何标记为“代码已实现但依赖环境”的条目，都必须附阻塞条件；不能写成“已验证”。

## 2. 一句话设定

**Roomie 是一间可 DIY 的虚拟放映室，让用户用音乐、空间和角色动作邀请朋友低压力地一起听。**

## 3. 总体目标与用户价值

**一句话目标：**交付一个可运行、可演示、可验证的 Roomie 微信小程序，完成“进房间 → 一起听 → 邀请好友 → DIY 房间 → 分享明信片”的低压力音乐同频陪伴闭环。

目标用户是 18–28 岁、习惯深夜听歌或看电影、需要陪伴但不喜欢强社交压力的人。产品把“发一条邀请消息”转译成“来我家坐坐”：个人房间、唱片墙和装修风格先替用户表达，再通过同步播放和轻量动作完成破冰。

核心价值按优先级排序：

1. **同频陪伴**：进入同一房间，看到同步播放和同频度。
2. **低压力表达**：通过房间布置、唱片墙和角色动作表达兴趣。
3. **可分享留存**：把房间生成明信片，形成可转发的房间名片。

## 4. 小程序机制

### 4.1 应用壳与导航

- `app.json` 注册 10 个页面，使用自定义五项 Tab：首页、好友、创建、消息、我的。
- 中央“创建”按钮为凸起绿色入口，聚合建筑师模式、发起放映和生成明信片。
- 自定义 Tab 只负责切换页面和读取 `roomie_unread` 角标；页面在 `onShow` 更新选中项。
- 页面需要自定义导航时，必须读取安全区高度并以 px 注入样式；不能把状态栏 px 当作 rpx。

### 4.2 首页机制

首页展示 LIVE 胶囊、房间主视觉、在线好友卡片和内嵌播放器。

- 点击房间插画进入 `/pages/room/room`。
- 点击播放器进入 `/pages/song/song`。
- “一起听”按钮给出邀请反馈，不声称已建立真实好友会话。
- 分享按钮调用 `wx.showShareMenu`；`onShareAppMessage` 返回房间标题、首页路径和 `room-postcard.jpg` 缩略图。

### 4.3 播放器机制

`utils/player.js` 是唯一播放器状态机，歌单包含 3 首 mock 曲目。

- 状态：`playing`、`index`、`position`。
- 派生快照：当前曲目、时长、进度百分比、格式化时间、歌词索引和歌单长度。
- 行为：播放/暂停、上一首、下一首、循环切歌、百分比 seek。
- 页面与 `mini-player` 通过 `subscribe()` 接收快照；组件在页面显示时订阅，隐藏或销毁时退订。
- 歌曲页把歌词索引映射到 `scroll-into-view`，并提供歌词/评论 Tab、互动栏和控制栏。
- Demo 不加载真实音频流；曲名和少量歌词只用于演示状态变化。

### 4.4 房间机制

房间页是可点击的等距 2.5D 场景，底图为 `room-interactive.webp`。

- 个人角色 MOMO 为原创橙色圆团子，联机角色 KIKI 为原创黄色团子；两者使用同一尺寸、同一光影和同一透明边界规范。
- 角色使用 `idle`、`walk-a`、`walk-b`、`sit` 精灵图；百分比坐标与底图保持一致。资源由 `tools/gen-characters.js` 手写 SVG 生成（原创，无版权风险），页面接口不绑定具体绘制来源。
- 可行走区域必须贴合底图的地板菱形（`room-map.js` 内的 uv 参数化约束），占房间可视地面 45% 以上；角色位置始终被约束在菱形内，不得走到墙面或天空区域。
- 房间页与双人页的舞台必须为正方形画幅（`room-frame` / `duo-stage`），完整显示底图、不做 `aspectFill` 裁切；轻触坐标与底图百分比一一对应。
- 点击空白区域生成目标点；`room-map.js` 统一导出 `isBlocked` / `clampToFloor` / `resolveTarget` / `findPath`（网格 A* 寻路），`room` 与 `duo` 两页共用同一份边界与障碍物，不各自拷贝。
- 角色按纵深（`top` 百分比）做 0.8–1.05 倍缩放，并与家具按 z 序排列，保证"走近前景变大、走到家具后被遮挡"的空间感；移动过程广播位置并交替行走帧，脚底阴影必须保留。
- 家具交互包括唱片墙（胡桃木层板 + 封套/黑胶混排）、唱机柜、放映机、沙发、落地灯、吉他角和地面唱片；交互结果写入 `roomState` 并显示提示气泡。
- 放映机控制投影光束，落地灯控制色温叠加，沙发切换坐下姿态，唱片物件触发播放提示；地面唱片为可跨越的装饰，不构成碰撞。
- 家具显隐必须由 `roomie_room.furniture` 驱动：未选择的家具不渲染覆盖层，其碰撞区域同时移除（`room-map.js setActiveFurniture`）；茶几、墙面装饰与地面唱片为固定件。
- 唱片墙的 12 个槽位按 `roomie_records` 选择顺序映射封面（`utils/records.js` 共享数据），未选满的位置显示空槽虚线；点击唱片墙必须展示当前挂载数量与正在播放曲目。
- 互动物件的名称标签默认隐藏，仅在角色靠近、点按或首访提示期浮现；不得常驻虚线框与调试感标签。
- `onShow` 读取 `roomie_room`，让建筑师模式保存的地板和灯光回到房间后生效。

### 4.5 多人同步机制

`room-sync.js` 与 `tools/sync-server.js` 构成本地演示中继。

- 客户端消息：`join`、`move`、`state`、`player`、`action`。
- 服务端按房间广播 `peer-join`、`peer-leave`、移动、状态和动作；发送者不接收自己的消息。
- 播放同步：`player` 消息携带 `{ index, position, playing, sentAt }`；本地切歌/播放暂停/seek 跳变即时报，播放中每 5 秒心跳校正；服务端按房间缓存最近一次播放状态，新加入者补发。
- 对端通过 `Player.applyRemote()` 应用播放状态：进度误差 ≤2.5 秒不校正，playing 时按 `sentAt` 补偿延迟；控制权为 last-write-wins（Demo 期不锁控制权）。
- 连接生命周期：`join()` 幂等（连接中/已连线直接复用），旧 socket 的事件不得改变状态；页面只在 `onShow` 恢复连接。
- 移动消息节流 150ms；对端位置使用插值动画，不重复做碰撞计算。
- 连接失败、关闭或异常时启动本地游走 peer；页面通过 `syncOnline` 呈现是否连线。
- 模拟器使用 `127.0.0.1`；真机需改为局域网 IP，并在同一网络中运行中继服务。

### 4.6 好友、邀请与双人同频

- 好友页按在线/离线分组展示状态标签。
- 对在线好友可直接进入或发起邀请；邀请按钮进入“等待中…”并防止重复点击。
- Demo 在约 1.5 秒后模拟对方接受，确认后进入 `/pages/duo/duo`。
- 消息页展示邀请和动态通知；点击消息标记已读，接受按钮直达双人房。
- 双人页展示双方角色、同频度 95–99% 的演示值、控制权文案和共享播放器。
- 退出双人房前弹窗确认；自动代开播只有在用户未操作控制栏时才恢复暂停。

### 4.7 建筑师模式

- 家具库支持多选；当前实现提供 13 件家具（含吉他角），清单与 `utils/room-layout.js` 同源。
- 家具图标必须使用 `tools/gen-room-scene.js` 生成的统一双色 WebP 图标，不使用系统 emoji。
- 预览区必须与房间页同源渲染：底图 + 选中家具覆盖层 + 当前唱片墙槽位 + 地板色温叠加。
- 地板提供 3 种颜色；选中态必须清楚显示。
- 灯光滑杆范围为 2700K–6000K，拖动时实时预览，提交时写入最终值。
- 保存写入 `roomie_room`，并使房间页在返回后立即应用灯光、地板与家具显隐。
- 保存按钮要区分“保存”和“已保存”，避免重复提交。

### 4.8 我的放映室

- 角色卡展示 MOMO、等级和建筑师徽章；换发型/换服装为占位入口，必须给出明确反馈。
- 唱片墙从 24 张收藏中最多选择 12 张；超限时提示，不得静默截断。
- 零选择时展示引导空态；保存写入 `roomie_records`。
- 读取旧缓存时过滤无效唱片 ID，避免页面崩溃。

### 4.9 建筑明信片与分享

- 使用 Canvas 2D 绘制米白底、房间插画、标语“有音乐的房间，抵千万句寒暄”和 ROOM ID 页脚。
- 明信片必须使用当前唱片墙选择：`roomie_records` 中最多 6 张唱片以封面色块 + 黑胶圆心的形式绘制在插画下方；画布内只用色块绘制，不解码 WebP 封面图。
- Canvas 未就绪时禁止保存并提示等待；保存中按钮显示“保存中…”。
- 保存失败时提示重试；相册权限不足时提供 `wx.openSetting` 入口。
- `onShareAppMessage` 返回房间文案并回到首页；分享缩略图使用 JPG 资产。

### 4.10 异常与空态

- 消息列表为空时展示空态说明。
- 唱片墙未选择时展示引导提示。
- 邀请、保存和相册授权操作必须有重复点击保护、失败反馈和可恢复路径。
- 房间同步不可用时回退模拟 peer，并将 LIVE 状态显示为未连线，而不是伪造实时成功。

## 5. 数据与接口契约

| 名称 | 位置 | 用途 | 约束 |
| --- | --- | --- | --- |
| `roomie_room` | 微信 Storage | `floor`、`lightTemp`、`furniture` | 读取必须经过 `normalizeRoom`；`furniture` 驱动场景显隐与碰撞 |
| `roomie_records` | 微信 Storage | 唱片墙选中的 ID 数组 | 最多 12 个，读取过滤失效 ID；房间槽位与明信片共用 `utils/records.js` |
| `roomie_unread` | 微信 Storage | 消息 Tab 未读角标 | 消息页查看或标记后同步清零/减少 |
| `Player.snapshot()` | 内存单例 | 三个播放器页面的共享快照 | 页面不得复制计时器或歌单 |
| `Player.applyRemote(msg)` | 内存单例 | 应用对端播放状态 | 2.5s 容差 + sentAt 补偿；emit 带 `remote` 标记防回播 |
| `RoomSync.join(options)` | 内存/Socket | 加入房间并注册事件处理器 | 幂等；离开页面必须调用 `leave()` |
| `RoomSync.sendPlayer(state)` | Socket | 广播播放状态 `{index, position, playing}` | 跳变即时报 + 播放中 5s 心跳；服务端按房间缓存并补发给新加入者 |

## 6. 总体视觉风格

### 6.1 视觉关键词

深夜蓝夜景、米白纸张、胡桃木、2700K 琥珀暖光、绿色 LIVE 状态、等距 2.5D 微距房间、黑胶唱片与复古收藏、低压力的 Q 版团子角色。外部空间用深蓝冷色，房间内部用米白/胡桃木/暖黄，绿色只留给 LIVE、主 CTA 与正向状态。

### 6.2 设计令牌

令牌以 `miniprogram/app.wxss` 为准（深夜放映室 v2）：

- 页面底色：`--night #0C1424`；深色面板：`--night-2 #121D32` / `--night-3 #1B2A45`；夜底文字 `--night-text #F2ECDC` / `--night-sub #8B96AC`。
- 纸张：`--paper #F6EFDD` / `--paper-2 #ECE2CB`；墨色：`--ink #26221A`；次级：`--ink-2 #6E6656` / `--ink-3 #9A9080`；分割线 `--line #E3D9C2`。
- 主绿：`--green #2FBF71`；深绿：`--green-deep #1F9D5A`；浅绿：`--green-soft #DFF5E9`。
- 琥珀：`--amber #F0A93C` / `--amber-deep #C9821E`；胡桃木：`--wood #8A5A33` / `--wood-deep #54371D`；暖光 `--warm-light #FFD9A0`；危险 `--danger #E2604C`。
- 卡片圆角：`32rpx`；胶囊圆角：`999rpx`；纸张阴影 `--shadow-paper`、绿色立体阴影 `--shadow-green`。
- 中文优先 MiSans/系统字体；英文标题可使用 Oranienbaum/Times 回退。
- 页面与组件只允许消费 `var(--*)` 令牌，禁止散落硬编码 hex。

### 6.3 组件规则

- 主操作使用绿色实心胶囊按钮；次操作使用绿色描边按钮。
- LIVE、在线和“正在播放”使用统一绿色胶囊，不用红色警告语义。
- 页面标题采用中文主标题加小号英文副标题；不要在业务页引入新的字体体系。
- 互动提示使用短句和轻量气泡；状态变化必须能被用户看见。
- 角色必须保留脚底接触阴影、统一光源方向和家具遮挡关系；不得直接把带白底的参考图放进房间。
- 角色资产为 `tools/gen-characters.js` 生成的原创 Q 版团子（橙色 MOMO / 黄色 KIKI），已替换早期抠图临时素材；替换后续版本时保留相同文件接口（`char-{momo,kiki}-{idle,walk-a,walk-b,sit}.webp`，144×184）以避免改动页面逻辑。

### 6.4 室内布局与唱片墙参考

本项目采用“可居住的音乐工作室 + 小型唱片画廊”作为空间基调。用户提供的参考素材转译为以下设计规则：

完整参考图存放在 `reference-assets/room-inspiration/`，仅用于设计评审，不进入小程序运行时包。

| 参考方向 | 必须保留的设计信号 | 在 Roomie 中的落地 |
| --- | --- | --- |
| 凌乱客厅排练室 | 乐器、音箱、线材和家具共同形成真实使用痕迹 | 房间保留鼓、吉他、键盘、音箱等 2–3 个层次，装饰集中在墙角和地面，不遮挡角色路径 |
| R&B 音乐小屋 | 混合海报、肖像、唱片和乐器的个人收藏墙 | 唱片墙允许封套、黑胶和海报混排，主视觉围绕放映墙形成“兴趣拼贴” |
| 白墙模块展陈 | 统一网格、透明框、间距和射灯 | 建筑师模式提供规则网格布局，卡片有细微投影和暖光边缘 |
| 木质层板唱片墙 | 深色木层板、横向节奏、封套与黑胶交替 | 默认唱片墙使用 2–3 层胡桃木层板，采用“封套—黑胶—封套”节奏 |
| 个人乌托邦收藏墙 | 规整重复、颜色分组、收藏可读性 | 唱片墙选择结果按行列展示，允许按色彩或收藏顺序排列 |
| 海外黑胶器材墙 | 老式唱机、功放、音箱和密集唱片库 | 放映机/唱机成为场景锚点，底部用柜体或唱片库承接视觉重量 |

#### 布局约束

- 角色可移动区域必须占房间可视地面的 45% 以上；唱片墙和装饰不得覆盖路径障碍物之外的主要通道。
- 主唱片墙应位于角色首次进入视线的墙面，面积约占背景墙 25%–40%，避免缩成不可读的小贴图。
- 装饰采用“大件锚点 + 中件陈列 + 小件噪点”三级层次；每个画面最多 1 个大锚点、3–5 个中件、若干小件。
- 材质至少区分墙面、木材、黑胶、金属和织物；不能所有物件都使用同一平面插画质感。
- 灯光默认从左上或放映墙方向进入，唱片和木层板产生柔和投影；灯光色温变化只改变氛围，不改变家具结构。
- 参考图中的真实海报、唱片封面、品牌标识和平台水印不得直接进入提交包；使用原创抽象封面、几何图形或已授权素材替代。

#### 视觉验收

- 缩略图状态下仍能分辨唱片墙、唱机、放映墙和角色位置。
- 房间截图同时具备“有人生活过”的轻度凌乱和可理解的视觉秩序。
- 切换 2700K/6000K 后，角色、唱片和木层板仍保持足够对比度。
- 点击唱片墙、唱机和层板物件时，均有明确状态反馈，不把装饰做成不可交互的死图。

## 7. 必须交付的闭环

以下路径必须从冷启动可重复走通：

1. 首页看到“深夜放映室 · 放映中”，点击房间插画进入房间。
2. 房间页点击放映机/灯光/家具，能看到状态反馈和角色移动。
3. 点击播放器进入歌曲详情，完成播放/暂停、切歌、seek 和歌词高亮。
4. 好友页邀请 NANA 或进入 KIKI 房间，看到等待、接受和双人同频页。
5. 双人页看到同频度、控制权和共享播放器，能够退出。
